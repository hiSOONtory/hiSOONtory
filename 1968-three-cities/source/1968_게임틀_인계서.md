# 인계서: 「1968, 세 도시의 학생」 게임 틀 제작

> 이 문서는 새 채팅에서 게임 틀(엔진과 화면)을 만드는 작업자에게 넘기는 작업 지시서다.
> 대사는 선생님이 따로 쓰고 있다. **이번 작업은 대사 없이도 처음부터 끝까지 돌아가는 게임 틀을 만드는 것**이다.
> 대사가 오면 엑셀을 변환기에 넣기만 하면 게임에 들어가야 한다.

## 0. 함께 받는 파일

| 파일 | 내용 | 언제 보나 |
|---|---|---|
| `1968_스토리보드.md` | 게임 틀, 흐름, 화면 6종, **장면 29개 상세**, 인물, 플래그, 대사 규칙, 논술 | 장면 목록·화면 구성을 확인할 때. 이 문서의 상위 기준 |
| `1968_대사작성양식.xlsx` | 선생님이 대사를 채우는 엑셀. 장면마다 빈 줄과 선택지 뼈대가 들어 있음 | 변환기(xlsx → JSON)를 만들 때. **이 파일 구조가 데이터 형식의 기준** |

두 파일이 이 문서와 어긋나면 질문할 것. 스토리보드의 장면 ID(`PA-2`, `MX-6` 등)는 바꾸지 않는다.

---

## 1. 무엇을 만드나

- **교과:** 고등학교 「역사로 탐구하는 현대 세계」(2022 개정)
- **대상과 환경:** 고등학생이 학교 크롬북이나 PC에서 **혼자** 플레이한다. 1~2차시(약 80분)에 걸쳐 하고, 끝나면 수업에서 논술을 쓴다.
- **줄거리:** 2026년의 고등학생(플레이어)이 탐구 과제로, 1968년에 열일곱 살이었던 세 사람(파리 클레르, 프라하 토마시, 멕시코시티 루시아)을 화상 통화로 인터뷰한다. 인터뷰가 시작되면 1968년으로 돌아가 그 학생이 되어 플레이한다.
- **게임 틀:** 선택형 비주얼 노벨(본편)에 2026 구술 인터뷰(바깥 액자)를 씌우고, 조사 화면과 사료 수첩을 더한다.
- **핵심 원칙:** 점수, 게이지, 승패를 두지 않는다. 선택은 개인의 경로만 바꾸고 역사적 결말은 바꾸지 않는다.
- **참고:** 기존 교육용 역사 게임 Attentat 1942의 '증언 인터뷰 + 회상 플레이' 구조와 비슷하다. 구조만 참고하고 그림·장면·UI는 가져오지 않는다.

## 2. 이번 작업 범위

**한다**
1. 게임 엔진: 장면 재생, 선택, 조건 분기, 플래그, 저장과 이어하기
2. 화면 9종(아래 4장)
3. 변환기: `1968_대사작성양식.xlsx` → `scenes.json`
4. **임시 데이터:** 대사가 비어 있어도 전체 흐름을 끝까지 플레이할 수 있는 자리표시 데이터
5. 결과지 화면과 출력
6. 교사용 장면 건너뛰기 모드

**하지 않는다**
- 대사 창작. 자리표시 문구는 `[PA-2 ① 진입: 대사 예정]`처럼 **누가 봐도 임시인 형태**로만 쓴다.
- 사료 카드 본문 확정. 사료 원문은 선생님이 확인한다. 실존 인물(드골, 둡체크 등)의 말을 지어내지 않는다.
- 최종 그림. 배경과 인물은 자리표시 그래픽으로 만들고, 나중에 이미지 파일로 바꿔 끼울 수 있게 한다.

## 3. 플레이 흐름

```
타이틀
 → FR-0  2026 교실: 이름 입력, 과제 받기, 1968 뉴스 몽타주
 → FR-H  허브: 인터뷰 카드 3장 + 1968 세계 달력 (세 도시 모두 필수, 순서 자유)
      도시 하나 = [X-I 인터뷰 도입] → [X-1 … X-6 1968 장면] → [일기] → [X-O 인터뷰 마무리]
 → (세 도시를 다 마치면) FR-X 교차 인터뷰 → FR-C 원인 카드 분류 → FR-E 에필로그 → 결과지
```

- 허브에서는 마친 도시에 완료 표시를 하고, 세 도시를 다 마쳐야 FR-X가 열린다.
- **1시간 축약판:** 설정 하나로 파리와 프라하만 필수로 하고, FR-X는 클레르–토마시 조합만 보여 준다. URL 파라미터 `?mode=short`로 켠다.
- 장면 목록과 각 장면의 내용은 `1968_스토리보드.md` 4장을 따른다(총 29개: 공통 5, 도시별 8 × 3).

- 장면 전환 시 자동 저장

## 5. 데이터 형식

### 5.1 엑셀 구조 (변환기 입력)

`1968_대사작성양식.xlsx`의 `대사_파리`, `대사_프라하`, `대사_멕시코`, `대사_공통` 네 시트를 읽는다.

| 열 | 이름 | 뜻 |
|---|---|---|
| A | 장면ID | `PA-2` 등 |
| B | 줄 | 장면 안 순번(무시해도 됨. 행 순서를 따른다) |
| C | 유형 | 아래 표 |
| D | 화자 | 인물 이름. 노년은 `클레르(노년)` |
| E | 표정·연출 | 자유 메모. 조사 줄에서는 **클릭 지점 이름** |
| F | 내용 | 실제 문장 |
| G | 조건 | 이 줄이 나오는 조건 |
| H | 플래그 설정 | 이 줄(주로 선택지)을 고르면 켜지는 플래그 |
| I | 비트·작성 메모 | 작가용 안내. **게임에서는 무시** |

- 1행은 머리글. **A열이 `■`로 시작하는 병합 행은 장면 정보 행이므로 건너뛴다.**
- **F열(내용)이 비어 있는 줄은 무시한다.** 단, 자막·사료·선택·이유태그 줄은 엑셀에 미리 채워져 있다.
- 유형(C열)이 비어 있고 내용이 있으면: 화자가 있으면 `대사`, 없으면 `내레이션`.

| 유형(엑셀) | JSON `type` | 동작 |
|---|---|---|
| 자막 | `caption` | 날짜·장소 자막 표시 |
| 내레이션 | `narration` | 화자 없는 대사창 |
| 대사 | `say` | 화자 있는 대사창 |
| 속마음 | `thought` | 주인공 생각(기울임, 다른 색) |
| 사료 | `source` | 사료 카드 팝업 + 수첩 저장 |
| 조사 | `inspect` | 연속된 조사 줄을 묶어 조사 화면 하나로. E열 = 지점 이름, F열 = 설명 |
| 선택 | `choice` | **연속된 선택 줄을 하나의 선택지 묶음으로.** 묶음 안 순서대로 기호 A, B, C… |
| 결과 | `result` | 내레이션처럼 표시(조건과 함께 씀) |
| 이유태그 | `reason` | 이유 태그 화면. F열은 `/`로 나눈 태그 목록 |
| 질문 | `question` | 인터뷰 질문 선택지. 연속된 질문 줄이 한 묶음, 기호 Q1, Q2… |
| 일기질문 | `diary` | 일기 화면. F열 = 질문 |
| 연출 | `direction` | 효과음, 암전 등 연출 지시. 처음엔 지원하는 키워드만 처리하고 나머지는 무시(5.3) |

### 5.2 조건과 플래그 문법

**조건(G열)**: 비어 있으면 항상 표시.

| 쓰는 법 | 뜻 |
|---|---|
| `선택=A` | 이 장면의 바로 앞 선택지 묶음에서 A를 골랐을 때 |
| `질문=Q1` | 바로 앞 질문 묶음에서 Q1을 골랐을 때 |
| `F_FACTORY` | 플래그 F_FACTORY가 켜져 있을 때 |
| `F_FACTORY 없음` | 플래그가 꺼져 있을 때 |
| `F_TLAT=B` | 값이 있는 플래그가 B일 때 |

조건이 여러 개면 `,`로 잇고 모두 만족해야 한다(AND). 문법에 맞지 않는 조건은 변환기가 **경고 목록**에 출력한다.

**플래그(H열)**: `F_PAVE`는 참으로 켜기, `KEEP_PA=B`는 값 넣기. 플래그 목록과 반영 위치는 스토리보드 7장.

**분기 규칙:** 결과 줄은 조건에 맞는 것만 순서대로 보여 주고 다시 본 줄거리로 합류한다. 장면 사이 점프(goto)는 없다. 장면 순서는 흐름(3장)이 정한다.

### 5.3 연출 키워드 (처음 지원할 것)

`암전`, `밝아짐`, `화면 흔들림`, `효과음: <이름>`, `배경: <배경ID>`, `인물: <이름> 등장/퇴장`. 이름이 맞는 음원·이미지가 없으면 조용히 건너뛴다.

### 5.4 JSON 예시 (변환 결과)

```json
{
  "id": "PA-2",
  "city": "PA",
  "kind": "scene",
  "title": "바리케이드의 밤",
  "bg": "PA-2",
  "lines": [
    {"type": "caption", "text": "1968년 5월 10일 밤 · 게뤼삭 거리"},
    {"type": "say", "speaker": "마르크", "text": "클레르! 이쪽!"},
    {"type": "inspect", "spots": [{"name": "벽 낙서", "text": "…"}, {"name": "라디오", "text": "…"}]},
    {"type": "source", "sourceId": "S03"},
    {"type": "choice", "options": [
      {"key": "A", "text": "보도블록을 함께 나른다", "set": {"F_PAVE": true}},
      {"key": "B", "text": "다친 학생을 응급소로 옮긴다"},
      {"key": "C", "text": "아파트 문을 두드려 몸을 피한다"}]},
    {"type": "result", "text": "…", "if": [{"choice": "A"}]},
    {"type": "reason", "tags": ["신념", "가족", "친구", "두려움", "호기심", "분노"]},
    {"type": "thought", "speaker": "클레르", "text": "…"}
  ]
}
```

- 사료 본문은 `사료목록` 시트(번호, 장면ID, 사료 후보, 원문 확인, 정확한 출처, 번역문, 한 줄 설명)에서 읽어 `sources.json`으로 따로 만든다. 사료 줄은 같은 장면ID의 사료를 행 순서대로 연결한다. 번역문이 비어 있으면 '사료 후보' 열을 `[확인 전]` 표시와 함께 보여 준다.
- 장면 메타(제목, 도시, 종류, 날짜)는 스토리보드 기준으로 `meta.json`에 미리 넣어 두고, 엑셀에서는 줄(lines)만 가져와도 된다.

### 5.5 변환기

- `tools/xlsx2json.py` (Python, openpyxl) 또는 Node 스크립트 중 하나. 실행 한 줄로 `data/scenes.json`, `data/sources.json`을 만든다.
- 출력: 장면별 줄 수, 빈 장면 목록, **조건·플래그 오류 경고**, 50자 넘는 대사창 목록, 15자 넘는 선택지 목록.
- 선생님이 개발 환경 없이도 쓸 수 있게, 게임의 교사 모드에 **엑셀 파일 끌어 놓기 → 즉시 미리보기** 기능이 있으면 좋다(SheetJS 사용, 선택 사항).

## 6. 저장과 이어하기

- 2차시에 걸쳐 플레이하므로 **필수**다.
- 장면 시작마다 `localStorage`에 자동 저장: 현재 위치, 플래그, 선택 기록, 이유 태그, 일기, 사료 수첩, 원인 분류, 이름.
- **이어하기 코드:** 기기가 바뀌는 경우를 위해 저장 상태를 압축해 짧은 코드로 보여 주고(결과지와 도시를 마칠 때마다 표시), 타이틀에서 입력하면 복원한다. 학생 개인정보(이름 외)는 넣지 않는다.
- `localStorage`가 막힌 환경에서도 게임은 돌아가야 한다(try/catch).

## 7. 교사 모드

- `?teacher=1`: 장면 목록에서 아무 장면이나 바로 열기, 플래그 수동 켜고 끄기, 대사 넘김 빠르게.
- 장면 정보(목적, 필수 사실, 작가 메모) 보기 토글. 수업 미리보기와 대사 검수에 쓴다.

## 8. 시각과 소리

- **분위기:** 1968년 실크스크린·판화 포스터. 도시마다 원색 하나: 파리 빨강, 프라하 파랑, 멕시코시티 초록. 2026 인터뷰 화면은 대비되게 밝고 깔끔한 현대 UI.
- **자리표시 그래픽:** 배경은 장면ID별 단색 판화풍 구성(CSS/SVG/Canvas로 간단히), 인물은 실루엣 도형 + 이름. `assets/bg/<장면ID>.webp`, `assets/char/<이름>.webp` 파일이 생기면 자동으로 바꿔 쓰는 구조.
- **글꼴:** 한글 가독성 우선(예: 본문 IBM Plex Sans KR, 제목 Black Han Sans 계열). 외부 폰트가 막혀도 시스템 글꼴로 대체.
- **소리:** 효과음만(라디오 잡음, 군중, 타자기 등), 기본 꺼짐 또는 작은 음량. 사용자 조작 뒤에만 재생.
- **폭력 표현:** 화면에 직접 그리지 않는다. 소리, 빛(조명탄), 암전, 다음 날 아침 장면으로 처리.

## 9. 기술 조건

- 빌드 도구 없이 돌아가는 **정적 웹**(HTML + CSS + JS 모듈 + JSON). 프레임워크는 꼭 필요할 때만.
- 배포: Cloudflare Workers(정적 자산). 선생님의 기존 콘텐츠도 `*.hisoontory.workers.dev`로 배포되어 있다. 저장소와 배포 이름은 선생님과 정한다(예: `1968-three-cities`).
- 대상 기기: 크롬북(1366×768), 학교 PC, 태블릿. **가로 화면 우선**, 세로 휴대폰에서도 깨지지 않을 정도.
- 접근성: 키보드만으로 진행 가능, 포커스 표시, 글자 크기 조절, `prefers-reduced-motion` 존중.
- 외부 서버로 학생 데이터를 보내지 않는다. 결과 제출 방식(출력·PDF 저장 vs 구글 시트 자동 제출)은 **아직 미정**이다. 출력과 복사를 먼저 만들고, 제출 기능은 끼울 자리만 남긴다.

## 11. 완료 기준

1. 자리표시 데이터로 **타이틀부터 결과지까지 세 도시를 끝까지 플레이**할 수 있다.
2. 스토리보드의 장면 29개가 모두 ID대로 존재하고 흐름 순서대로 이어진다.
3. `1968_대사작성양식.xlsx`의 `예시` 시트(PA-2 일부)를 `대사_파리`의 PA-2 자리에 붙여 넣고 변환하면, 게임에서 그 대사·선택·조건 분기가 그대로 나온다.
4. 플래그가 뒤 장면에 반영된다(예: PA-3에서 A를 고르면 PA-4 조건 줄이 나옴).
5. 브라우저를 닫았다 열어도 이어서 할 수 있고, 이어하기 코드로 다른 브라우저에서 복원된다.
6. 결과지가 A4 한두 장으로 출력된다.
7. 크롬북 해상도(1366×768)에서 대사창·선택지가 잘리지 않는다.
8. `?mode=short`, `?teacher=1`이 동작한다.

## 12. 진행 방식

- 먼저 **엔진과 화면 2·4·6(장면, 선택, 인터뷰)만으로 PA-I → PA-2 → PA-O**가 돌아가는 최소판을 만들어 선생님께 보여 주고 확인받은 뒤 나머지를 넓힌다.
- 막히거나 이 문서로 판단이 안 되는 것은 추측하지 말고 선생님께 묻는다.
