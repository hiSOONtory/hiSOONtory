1왜 배포하나요?

파일을 보내면 학생이 "안 열려요" 합니다.
링크를 보내면 누르기만 하면 열립니다.

클로드가 만들어 준 HTML 파일은 내 컴퓨터에만 있는 '종이'와 같아요. 학생들이 보려면 이 종이를 인터넷 게시판에 붙여 두고 주소를 알려 줘야 합니다.

HTML 파일 = 인터넷 창(크롬·엣지)에서 열리는 문서 파일. 이름이 ○○.html로 끝나요.
배포 = 내 파일을 인터넷에 올려서 누구나 주소로 열 수 있게 만드는 일.

클로드가 만든 HTML→인터넷에 올리기(배포)→주소 1개→학생 휴대폰에서 바로 열림

세 가지 방법이 있어요. 오늘 처음이면 ① Cloudflare Drop부터 해 보세요.

①Cloudflare Drop — 가입 없이 1분

Cloudflare(클라우드플레어) = 전 세계에 인터넷 서버를 가진 회사. 파일을 올려 두면 주소를 만들어 줘요.

01

HTML 파일 받기

  • 클로드 화면에서 만든 파일의 다운로드 버튼을 눌러 내 컴퓨터에 저장해요.
  • 파일 이름은 그대로 두어도 된다고 안내되어 있어요. 확인 필요
    ※ 일부 안내 글에는 "index.html이 꼭 있어야 한다"는 말도 있어요. 올렸는데 오류가 나면 이름을 index.html로 바꿔 다시 올리세요.
캡처: 클로드 화면의
파일 다운로드 버튼
02

cloudflare.com/drop 접속

  • 크롬 주소창에 cloudflare.com/drop 을 입력하고 Enter.
  • 로그인하지 않아도 바로 열려요.
캡처: Cloudflare Drop
첫 화면
03

주황색 화면에 끌어다 놓기

  • 바탕화면의 HTML 파일을 마우스로 잡아서 화면 가운데 영역으로 끌어다 놓아요(드래그 앤 드롭).
  • 끌기가 어렵다면 Browse files확인 필요 같은 버튼을 눌러 파일을 골라요.
  • 폴더나 ZIP 파일도 올릴 수 있다고 안내되어 있어요.
캡처: 파일을 끌어다 놓는 영역
04

주소 확인 → 휴대폰으로 열어 보기

  • 몇 초 뒤 ○○.workers.dev 형태의 주소가 나와요. 주소 끝 확인 필요
  • 주소를 복사해서 내 휴대폰 카톡으로 보내 직접 열어 보세요. 학생이 보는 화면과 같아요.
캡처: 배포 완료 화면과
주소
05

⏰ 60분 안에 Claim 하기

  • 이 주소는 1시간짜리 임시 주소예요. 60분이 지나면 사라져요.
  • 화면의 Claim정확한 버튼 문구 확인 필요을 눌러 Cloudflare에 로그인하거나 새로 가입해요.
  • 가입할 때 이메일 인증을 요구하면 메일함에서 인증 링크를 눌러 주세요. 확인 필요
  • Claim을 끝내야 주소가 계속 남아요.

Claim(클레임) = "이 사이트는 내 거예요" 하고 내 계정으로 가져오기.

가입 화면

②GitHub Pages — 공개해도 되는 자료

GitHub(깃허브) = 파일을 보관하고 공유하는 인터넷 창고. GitHub Pages = 그 창고 안 파일을 웹페이지로 보여 주는 기능.

01

가입하고 저장소 만들기

  1. github.com 접속 → Sign up으로 가입.
  2. 오른쪽 위 + → New repository 클릭.
  3. Repository name 칸에 영어로 이름 입력 (예: suhaeng-2026).
  4. Public 선택 → Create repository 클릭.

무료 계정은 Public(공개) 저장소에서만 GitHub Pages를 쓸 수 있어요.

캡처: New repository 화면
(Public 선택 부분)
02

파일 이름을 index.html로 바꾸기

  • 내 컴퓨터에서 파일에 마우스 오른쪽 클릭 → 이름 바꾸기.
  • index.html 로 바꿔요. (모두 소문자, 띄어쓰기 없이)
  • "확장자를 바꾸면…" 경고가 나오면 예.
캡처: 파일 이름 바꾸기
03

파일 올리기 → Commit changes

  1. 방금 만든 저장소 화면에서 uploading an existing file 링크 클릭.
    (링크가 안 보이면 Add file → Upload files)
  2. index.html을 화면에 끌어다 놓기.
  3. 아래 초록 버튼 Commit changes 클릭.

커밋(Commit) = "이 상태로 저장 확정!" 버튼. 게임의 세이브와 같아요.

캡처: 업로드 화면과
Commit changes 버튼
04

Pages 켜기

  1. 저장소 위쪽 메뉴의 Settings 클릭.
  2. 왼쪽 메뉴에서 Pages 클릭.
  3. Build and deployment → Source를 Deploy from a branch로.
  4. Branch를 main, 옆 칸은 / (root) → Save.

브랜치(branch) = 저장소 안의 '작업 줄'. 처음엔 main 하나만 있어요.

캡처: Settings → Pages 화면
05

1~2분 기다리면 주소 완성

  • 주소 모양: 아이디.github.io/저장소이름
  • 예) 아이디가 genius-jeong, 저장소가 suhaeng-2026이면
    genius-jeong.github.io/suhaeng-2026
  • Pages 화면 위쪽에 Your site is live at … 문구와 Visit site가 보이면 성공. 확인 필요
캡처: 사이트 주소가
표시된 화면
TIP 내용을 고치고 싶으면 같은 이름(index.html)으로 다시 올리고 Commit changes. 주소는 그대로라 학생에게 다시 보낼 필요가 없어요.

③GitHub + Cloudflare 연결 — 한 학기 내내

깃허브에 파일만 바꿔 올리면 Cloudflare가 알아서 새 버전을 올려 줘요. 저장소를 비공개로 두어도 됩니다. 확인 필요

01

GitHub에 index.html 올려 두기

  • 방법 ②의 01~03과 같아요. 단, 저장소를 만들 때 Private을 골라도 돼요.
  • Pages 켜기(04)는 하지 않아도 됩니다.
캡처: Private 저장소에
index.html이 올라간 화면
02

Cloudflare 대시보드 → Create application

  1. dash.cloudflare.com 접속 → 로그인(없으면 Sign up).
  2. 왼쪽 메뉴 Workers & Pages 클릭.
  3. Create application 클릭.

대시보드 = 내 계정의 관리 화면(설정판).

캡처: Workers & Pages 화면의
Create application 버튼
03

Import a repository 옆 Get started

  • Import a repository 옆의 Get started 클릭.

Import(임포트) = 깃허브 저장소를 Cloudflare로 '불러오기'.

캡처: Import a repository와
Get started 버튼
04

깃허브 연결 허용 → 저장소 고르기

  1. 처음이면 깃허브 계정을 연결하라는 화면이 떠요. 깃허브 창에서 허용(Install / Authorize) 버튼을 눌러요. 버튼 문구 확인 필요
  2. 돌아온 화면의 목록(또는 검색창)에서 내 저장소를 골라요.
캡처: 깃허브 연결 허용 화면과
저장소 목록
05

설정 그대로 → Deploy

  • 나오는 설정은 건드리지 말고 맨 아래 Save and Deploy 클릭.
    ※ 화면에 따라 Deploy라고만 적혀 있을 수 있어요. 확인 필요
  • 1~2분 뒤 ○○.workers.dev 주소가 생겨요.
캡처: 배포 완료 화면과
workers.dev 주소
TIP 다음부터는 깃허브의 index.html만 새 파일로 바꿔 올리고 Commit changes. Cloudflare가 자동으로 다시 배포해서 같은 주소에 새 내용이 나와요.

6꼭 지킬 것

🔒 개인정보는 HTML 안에 넣지 않기

링크를 아는 사람은 누구나 페이지를 볼 수 있어요. 학생 이름·학번·연락처·성적을 HTML 안에 적어 두지 마세요.

예) ❌ "10200 지니어스 정 — 수행평가 18점" 같은 목록을 페이지에 그대로 넣기

📝 구글 시트 제출 페이지도 같은 방법으로

학생이 답을 적어 제출하면 구글 시트에 쌓이는 페이지(Apps Script 연동)도 위의 세 방법으로 똑같이 올릴 수 있어요.
학생이 적은 답은 HTML이 아니라 선생님 구글 시트에 저장되니 안전해요.

Apps Script = 구글 시트에 붙이는 작은 자동화 프로그램.

7자주 막히는 곳

주소를 열었더니 "404"가 떠요.
404 = "그 페이지가 없어요"라는 뜻이에요.
① 파일 이름이 정확히 index.html인지 확인 (Index.HTML, index (1).html ❌)
② GitHub Pages라면 Settings → Pages에서 Branch가 main으로 저장됐는지 확인
③ 막 올렸다면 1~2분 기다린 뒤 다시 열어 보기
어제 만든 Drop 주소가 사라졌어요.
60분 안에 Claim을 하지 않으면 임시 주소가 지워져요. 처음부터 다시 올리고, 이번에는 바로 Claim까지 끝내 주세요.
파일을 고쳐 올렸는데 예전 내용이 보여요.
① 1~2분 기다리기 ② 새로고침(PC는 Ctrl+F5, 휴대폰은 창을 닫고 다시 열기)
③ 깃허브에 올린 파일 이름이 index.html 그대로인지 확인 (다른 이름으로 올리면 새 파일이 하나 더 생길 뿐이에요)
저장소를 Private으로 했더니 GitHub Pages 메뉴에서 막혀요.
무료 계정은 Public 저장소에서만 Pages를 쓸 수 있어요. 비공개로 두고 싶으면 방법 ③을 쓰세요.
학생이 "링크가 안 열려요" 해요.
주소를 손으로 옮겨 적다 틀리는 경우가 많아요. 주소를 복사해서 보내거나, QR코드로 만들어 칠판 화면에 띄워 주세요. 먼저 선생님 휴대폰에서 열리는지 확인하는 습관이 좋아요.
